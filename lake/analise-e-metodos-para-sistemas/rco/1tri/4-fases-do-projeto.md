### Slide 8

- Fases de um projeto de
- desenvolvimento de software
- Como toda atividade pode ser dividida em etapas, um projeto também deve ser dividido em fases, dado sua complexidade, tamanho etc.
- As fases de um projeto de desenvolvimento de software são:
- Concepção;
- Levantamento e análise de requisitos;
- Projeto (por ter o mesmo nome, aqui se decide como o software irá operar em termos de software ou infra estrutura);
- Fase de desenvolvimento;
- Implantação;
- Manutenção de software.

### Slide 11

- Escopo do projeto de desenvolvimento
- O escopo do projeto descreve o trabalho necessário para entregar um produto, um serviço ou um resultado tangível, é o mapeamento de todo o trabalho que será necessário para a conclusão do projeto.
- No escopo, há alguns aspectos que devem estar presentes, como a justificativa do projeto, os objetivos, as restrições, os recursos disponíveis e as partes interessadas (stakeholders).
- É comum que o escopo do projeto seja confundido com um conceito semelhante, o escopo do produto.

Questão 1

O desenvolvimento de projeto de softwares é composto por diversos tipos de fases, geralmente divididos em cinco principais. Como podemos descrever a fase de desenvolvimento?

a) É nessa etapa que as primeiras linhas de código começam a ser escritas.

b) Esta é a fase na qual levantamos a problemática do cliente.

c) Esta é a fase em que realizamos os testes de software.

d) É nesta fase que acontece a concepção.

Resposta comentada: Como todo o sistema já foi documentado (visualmente), resta aos desenvolvedores criarem o produto.

Questão 2

Análise de requisitos é o estágio que se concentra no desenvolvimento, coleta e análise de todos os requisitos de negócios do produto de software. Isso geralmente significa olhar para:

a) Elementos reunidos no produto final.

b) A arquitetura do software.

c) Experiência do usuário do software.

d) Quem será o usuário final do software.

Resposta comentada: Todo intuito da etapa de análise de requisitos pensa em quem vai ser o usuário final, ou seja, quem vai usar esse sistema.

ATIVIDADE PRÁTICA AULA 04

##### 1. Objetivo da Aula Prática

Ao final desta aula prática, o estudante será capaz de:

- Compreender, de forma aplicada, as fases de um projeto de desenvolvimento de software.
- Identificar a função de cada fase dentro do ciclo de um projeto.
- Desenvolver a habilidade prática de registrar e organizar etapas de um projeto.
- Representar um projeto de software por meio de uma narrativa visual, aplicando corretamente as fases do projeto.

##### 2. Ferramentas Recomendadas

###### Pixton (https://www.pixton.com/)

- Para que serve: Criação de histórias em quadrinhos digitais.
- Por que é adequada ao tema: Permite representar visualmente as fases do projeto de software.
- Como facilita o aprendizado: Ajuda o aluno a transformar conceitos abstratos em situações concretas.

###### StoryboardThat (https://www.storyboardthat.com/)

- Para que serve: Criação de storyboards e narrativas visuais.
- Por que é adequada ao tema: Facilita a organização sequencial das fases do projeto.
- Como facilita o aprendizado: Estimula o raciocínio lógico e a sequência de etapas.
(Outras ferramentas podem ser utilizadas conforme o material: Stripcreator, Pencil, entre outras, todas gratuitas ou com plano free.)

##### 3. Checklist Inicial

Antes de iniciar a prática, o estudante precisa ter:

- Computador ou notebook
- Conexão com a internet
- Acesso a uma das ferramentas de criação de HQ
- Caderno ou documento digital para anotações
- Ambiente: laboratório de informática ou sala com internet

##### 4. Passo a Passo do Docente (Aula de até 50 minutos)

###### Como conduzir a aula

- Retomada do conteúdo anterior
- Relembre o ciclo de vida de um software, conforme indicado no material.
- Conecte o tema com a necessidade de dividir projetos em fases.
- Contextualização
- Apresente o cenário da empresária Khyonara, que deseja desenvolver softwares com menor custo e tempo.
- Destaque que isso só é possível com organização por fases.
- Explicação da atividade prática
- Explique que os alunos irão criar uma história em quadrinhos representando um projeto de software.
- Reforce que as fases do projeto devem aparecer claramente.
- Acompanhamento
- Oriente os alunos durante a criação.
- Auxilie na identificação correta das fases.
- Socialização
- Reserve tempo para apresentação das produções.

###### Preparações necessárias

- Testar previamente o acesso às ferramentas.
- Apresentar novamente a lista de fases do projeto.

###### Alertas e pontos de atenção

- Alunos podem misturar as fases.
- Reforce a sequência:
- Concepção
- Levantamento e análise de requisitos
- Projeto
- Desenvolvimento
- Implantação
- Manutenção

###### Dinâmica sugerida

- Discussão inicial → criação guiada → apresentação.

###### Gerenciamento de tempo (50 minutos)

- Contextualização: 10 minutos
- Orientação da atividade: 5 minutos
- Execução prática: 25 minutos
- Apresentação e encerramento: 10 minutos

##### 5. Atividade Prática — Descrição Geral

###### O que o estudante deve produzir

- Uma história em quadrinhos que represente:
- Um cliente
- Um desenvolvedor
- Uma empresa
- Um produto de software
- As fases do projeto de software

###### Problema real simulado

- Organização e execução de um projeto de software do início ao fim.

###### Habilidade desenvolvida

- Planejamento de projetos.
- Registro e análise de etapas.
- Comunicação visual de processos.

##### 6. Metodologia Ativa Utilizada

- Aprendizagem baseada em projetos (PBL)
- Ensino por descoberta
- Aprendizagem criativa
- Elementos de Lemov aplicados:
- Check for Understanding
- Think-Pair-Share
- No Opt Out

##### 7. Passo a Passo da Atividade Prática (para os alunos)

- Escolha uma ferramenta de criação de histórias em quadrinhos.
- Defina o cenário do projeto (empresa, cliente e produto).
- Planeje a história incluindo as fases do projeto:
- Concepção
- Levantamento e análise de requisitos
- Desenvolvimento
- Manutenção
- Crie os quadros representando cada fase.
- Revise se todas as fases estão claras na narrativa.
- Salve ou exporte sua história.

##### 8. Exemplo ou Demonstração

###### Exemplo de Estrutura da História

- Quadro 1: Cliente apresenta o problema (Concepção).
- Quadro 2: Desenvolvedores levantam requisitos.
- Quadro 3: Planejamento e definição do projeto.
- Quadro 4: Desenvolvimento do software.
- Quadro 5: Entrega e manutenção do sistema.
(Exemplo apenas orientativo.)

##### 9. Resultado Esperado

O estudante deverá apresentar:

- Uma história em quadrinhos coerente.
- Uso correto das fases do projeto.
- Clareza na sequência e nos papéis envolvidos.
O professor poderá verificar:

- Se todas as fases estão representadas.
- Se a narrativa está organizada.
- Se o conceito de projeto foi compreendido.

##### 10. Formato de Entrega da Atividade

- O que deve ser enviado: Link, PDF ou imagem da história em quadrinhos
- Formato de nomeação: Aula04_FasesDoProjeto_NomeAluno
- Onde entregar: Plataforma definida pelo professor
- Prazo sugerido: Até o final da aula ou como tarefa para casa

##### 11. Encerramento e Reflexão

Finalize a aula com perguntas como:

- Por que dividir um projeto em fases é importante?
- O que pode acontecer se uma fase for ignorada?
- Como esse conteúdo se conecta com projetos reais de software?
- Em quais outras áreas da vida usamos fases para organizar tarefas?
