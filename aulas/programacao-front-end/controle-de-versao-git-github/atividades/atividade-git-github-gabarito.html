Exercício 1 — Fluxo (1,5)

NºComandoO que faz
1git addmarca o arquivo para a próxima foto (stage)
2git commit -mgrava a foto no histórico local, com mensagem
3git pushenvia os commits locais para o GitHub
4git pulltraz do GitHub os commits que não estão no local

Bônus: git init — cria a pasta .git, não move código entre lugares.
Aceitar git fetch + git merge no lugar do pull. Descontar 0,25 se escrever git commit sem entender que a foto sai do stage, não da pasta.

Exercício 2 — V ou F (1,0)

  • F — commit guarda o estado inteiro (fotografia), não só o diff.
  • F — branch é rótulo móvel; não duplica arquivo nenhum.
  • V — todo o ciclo local roda offline.
  • V — é exatamente o papel do .gitignore.
  • F — senha foi bloqueada em 2021; usar SSH ou GitHub CLI.
  • F — conflito é pedido de decisão humana, não erro nem corrupção.
  • F — clone baixa o histórico completo.
  • V — cada push na branch-fonte republica o site em ~1 min.

Exercício 4 — Terminal (1,5)

A mensagem do commit precisa dizer o que mudou; aceitar qualquer frase descritiva. Descontar se trocar a ordem add → commit → push.

Exercício 5 — Conflito (1,0)

a) Entre <<<<<<< HEAD e ======= está a versão da branch atual (main). Depois do =======, a versão de modo-escuro.

b) Qualquer redação sem nenhum marcador, ex.:

<section class="hero"> <h1>Encontre seu novo melhor amigo no Petfinder!</h1> </section>

Vale escolher uma das duas ou combinar as duas — o que não vale é sobrar <<<<<<<, ======= ou >>>>>>>.

c) git add index.html e depois git commit (aceita a mensagem de merge sugerida).

Exercício 6 — Conventional Commits (1,0)

OriginalEsperado (variações válidas)
“ajustes”feat: adiciona formulário de contato
“arrumei o bug”fix: corrige botão Enviar que não respondia no mobile
“mudei umas coisas”docs: corrige erros de digitação no README
“wip”chore: atualiza versão da dependência

0,25 cada. Prefixo certo com frase vaga (feat: mudanças) vale só metade — o padrão exige as duas partes.

Exercício 7 — .gitignore (0,5)

Versionar: index.html, css/estilo.css, img/pet1.jpg, README.md.

Ignorar:

node_modules/ · .env · *.log · anotacoes-pessoais.txt

Sobre o .env: apagar o arquivo não apaga a fotografia antiga — o commit anterior continua no histórico e no GitHub. Na prática, a senha vazou e precisa ser trocada, não só removida.

Exercício 8 — Fast-forward × merge commit (1,0)

Caso A: fast-forward — a main não recebeu commit novo, então o Git só empurra o rótulo. 0 commits novos criados.

Caso B: merge commit — as duas histórias divergiram. Esse commit tem 2 pais, um de cada branch.

Conflito: só pode acontecer no Caso B. No Caso A a main não mudou, então não existem duas versões concorrentes da mesma linha para o Git escolher.
