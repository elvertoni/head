Perguntas a caneta (0,9 · 0,3 cada)

1. O texto começa assim (os valores mudam conforme o que o aluno digitou):

?nome=Ana&email=ana%40exemplo.com&perfil=estudante
&dor=Fila+da+cantina

As palavras antes de cada = vêm do atributo name de cada campo. 0,15 pelo trecho copiado + 0,15 por citar name. Quem responder id errou: os dois têm o mesmo valor na folha, mas quem vai para o endereço é o name. Curiosidades que aparecem: o @ vira %40 e o espaço vira +.

2. O navegador não enviou e mostrou um aviso no campo. No Chrome: “Inclua um "@" no endereço de e-mail”. Quem causou foi o type="email". 0,15 pelo que aconteceu + 0,15 pela causa. Se responder required, dar só metade da causa: o required barra campo vazio, não e-mail mal escrito.

3. Os campos de nome, e-mail e texto longo ficaram mais largos e encostaram na borda direita do cartão. A lista e o botão não mudaram, então tudo ficou desalinhado. Motivo: sem border-box, os 100% valem só para o conteúdo, e o padding (10 + 10) e a borda (1 + 1) são somados por fora: 22px a mais. 0,15 pela observação + 0,15 pela explicação com as próprias palavras (“o padding passou a contar por fora”). A lista e o botão não mudam porque o navegador já calcula a largura deles com a borda incluída.

Vistos no computador (2,1)

  • HTML · 1,2. Os quatro campos e o botão aparecem, e enviar vazio é barrado. Tirar 0,15 por item: rótulo que não leva ao campo (for diferente do id), campo sem name, required faltando, lista sem a opção vazia.
  • CSS · 0,9. Conferido na tela: 0,3 pelo cartão centralizado (7), 0,3 pelos campos em linhas próprias e alinhados (8), 0,3 pelo contorno ao apertar Tab e pelo botão verde que escurece (9 e 10).

Desafio (bônus de até 0,3)

A. Entre o e-mail e a lista. O tipo é tel: no celular abre o teclado numérico, mas não valida o formato sozinho.

<label for="telefone">Seu telefone</label>
<input type="tel" id="telefone" name="telefone">

B. No HTML, antes do botão:

<label>
  <input type="checkbox" name="novidades">
  Quero receber novidades
</label>

A regra input { width: 100% } do passo 8 também vale para a caixa: ela ocupa a linha inteira e empurra o texto para baixo. Conserto, no fim do estilo.css:

input[type="checkbox"] {
  width: auto;
}

Aceitar também o conserto com uma classe na caixa.

C. O <form> inteiro vai para dentro da <section id="comecar"> da landing. Do CSS, levar os blocos form, label, input, select, textarea, :focus e button. Não levar o body: a landing já tem o dela, e o max-width: 420px estreitaria a página toda. Esse limite passa para o form. No lugar de #2f6f4e, usar var(--cor-destaque).
